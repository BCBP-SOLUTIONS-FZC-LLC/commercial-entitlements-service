# Contributing

This is an internal Commercial microservice for the XpertPMS platform. This guide covers development setup, how to extend the service, test requirements, and the PR process for `commercial-entitlements`.

## Prerequisites

- Go 1.26.11+ (matches `go.mod`)
- Docker (required for PostgreSQL + PgBouncer + Valkey + Floci integration tests via `testcontainers-go`)
- `golangci-lint` is managed as a Go tool (`go tool golangci-lint`) — no separate install needed
- `GOPRIVATE=github.com/BCBP-SOLUTIONS-FZC-LLC/*` (private module access; also `GONOSUMDB` for the same prefix)
- SSH key registered with the BCBP org so `go mod download` can fetch `platform-events`, `platform-gincommon`, `platform-pgcommon`, `platform-audit`

## Development setup

```bash
git clone https://github.com/BCBP-SOLUTIONS-FZC-LLC/commercial-entitlements
cd commercial-entitlements
make setup      # copies .env-example → .env and installs .githooks/pre-commit
make tidy       # go mod tidy
make docker-up  # start PostgreSQL + PgBouncer + Valkey + Floci (SNS/SQS/Glue, always free) + Temporal
make lint       # verify linter passes
make test       # run all tests (requires Docker)
make run        # start the server on :8080
```

To run only unit tests (no Docker required):

```bash
make test-unit
```

`make setup` installs `.githooks/pre-commit`, which runs `make tidy`, `fmt-check`, and `lint` before every commit.

## Project layout

```
cmd/
  server/            ← Composition root — wiring, pool setup, middleware, graceful shutdown
  reconciler/        ← Single binary dispatched via --job=<name>; drives 5 K8s CronJobs
  worker/            ← Temporal workflow worker (catalog fan-out)
  migrate/           ← Helm pre-install/pre-upgrade hook; applies schema migrations
  expiry/            ← Standalone addon/override expiry sweep
  catalog-refresh/   ← Pulls IAM plan catalog into Postgres + Valkey
internal/
  core/domain/       ← Entities, value objects, DomainError catalogue (no external deps)
  core/port/         ← Interfaces: repositories, cache, event publisher, inbox, IAM catalog client
  core/service/      ← Use cases (EntitlementsService, DrawdownService, OverrideService,
                       TrialService, ShortfallService)
  adapter/inbound/
    http/            ← Gin handlers, DTOs, middleware (ENT-I1..I3, ENT-T1, ENT-O1..O7)
    consumer/        ← 4 SQS consumers: billing, tenant, catalog, membership
    sqspipeline/     ← Platform-events SQS pipeline (DLQ router, schema validation, inbox claim)
  adapter/outbound/
    postgres/        ← Repository implementations + golang-migrate SQL migrations
    valkey/          ← Cache adapter (rueidis) — advisory-only (CACHE-1)
    eventbus/        ← Publisher (single SNS topic, GlueCodec) + outbox runner
    iamclient/       ← HTTP client for IAM Catalog service (plan definitions)
    auditrecorder/   ← platform-audit outbox mode (pending_audit_entries)
    metrics/         ← Tier 3 Prometheus collectors (commercial_entitlements_*)
  adapter/temporal/  ← Temporal workflow + activity definitions
api/asyncapi.yaml    ← AsyncAPI 3.0 — commercial-entitlements-events channel
docs/swagger/        ← OpenAPI 2.0, generated by `make swag`
internal/adapter/outbound/eventbus/schemas/
                     ← Embedded JSON Schema Draft-07 (1 file: tenant_entitlements_changed.json)
                       CLOSED schemas (additionalProperties:false)
test/                ← All tests: unit/, postgres/, integration/
```

**Dependency rule:** `domain` ← `port` ← `service` ← `adapter` ← `cmd`. Nothing in `core/` may import `adapter/`. `core/service` may import `internal/adapter/outbound/metrics` for business-outcome counters. Enforced in CI by `go-arch-lint` (`.go-arch-lint.yml`).

For full layout details see [`.claude/architecture.md`](.claude/architecture.md) and [ARCHITECTURE.md](ARCHITECTURE.md).

## Extending the service

### Adding a new domain entity or value object

1. Add the type to `internal/core/domain/` — no external imports allowed.
2. Add a `New*` constructor and validation logic in the relevant `internal/core/service/*.go` file.
3. Add unit tests in `test/unit/`.

### Adding a new use case (service method)

1. Add the method signature to the relevant interface in `internal/core/port/`.
2. Implement in `internal/core/service/`. All writes must use `pgcommon.RunInTx` — business row + outbox row share one transaction (EVT-10, CONS-1).
3. Add the handler in `internal/adapter/inbound/http/` and wire in `cmd/server/main.go`.
4. Add unit tests in `test/unit/`; integration coverage in `test/integration/` or `test/postgres/`.

### Adding a new HTTP endpoint

1. Add the handler in `internal/adapter/inbound/http/`, annotated with swag `@Summary`/`@Tags`/`@Router`.
2. Wire the route in `internal/adapter/inbound/http/router.go`. Route groups: `/api/v1/internal/*` (in-mesh), `/api/v1/tenants/*` (tenant-scoped JWT), `/api/v1/operator/*` (platform_operator role).
3. Run `make swag` and commit the regenerated `docs/swagger/*`. CI's `swag-check` target fails a PR that drifts.

### Adding a new repository migration

1. Add `NNNN_description.up.sql` and `NNNN_description.down.sql` to `internal/adapter/outbound/postgres/migrations/`. Numbering is **monotonic** — never reuse or reorder.
2. Verify: `make docker-up && make run` (migrations run at startup via `pgmigrate.Runner`).
3. Add or update RLS tests in `test/postgres/` for any new tenant-scoped table.
4. **`record_version` columns** — any new table with optimistic locking needs `record_version bigint NOT NULL DEFAULT 1`, the `touch_row()` BEFORE-UPDATE trigger (CONC-1).
5. **New indexes on tenant tables** must use `CREATE INDEX CONCURRENTLY` (rolling-deploy safety). Never combine `CREATE UNIQUE INDEX CONCURRENTLY` and `ADD CONSTRAINT USING INDEX` in the same release.
6. **Destructive changes** (column drops, type narrowing) always ship in a separate, later release (MIG-1).

### Adding a new domain event type

1. Add the payload struct to `internal/core/domain/event.go`.
2. Build the event in the relevant service method and pass to `port.EventPublisher.Enqueue` inside the same `RunInTx` as the business write (EVT-10).
3. Add the message and payload schema to `api/asyncapi.yaml`, then run `make extract-schemas` to derive the JSON Schema file. Commit both. Schemas are CLOSED (`"additionalProperties": false`).
4. Register the new event name in `cmd/server/main.go`'s `allSchemaNames` slice so `GlueCodec` resolves it at startup.
5. Update the event catalogue in `README.md` and `.claude/api-caching-events.md`.

## PR checklist

- [ ] `make ci` passes locally (tidy + fmt-check + vet + lint + arch-lint + test-ci + build)
- [ ] New behaviour has unit tests in `test/unit/`; DB behaviour has postgres tests in `test/postgres/`
- [ ] Migrations follow the additive-only rules (CONC-1, MIG-1, RLS-1)
- [ ] New events have a JSON schema + asyncapi.yaml entry (`make extract-schemas`)
- [ ] `CHANGELOG.md` updated under `[Unreleased]`
- [ ] `make swag` run if any handler annotation changed (commit `docs/swagger/`)
